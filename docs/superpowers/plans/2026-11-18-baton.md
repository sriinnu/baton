# baton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent-neutral handoff: distilled, always-current, inheritable briefs so any agent (Claude, Codex, Antigravity, Kimi, DeepSeek…) or subagent can continue work by session id or name.

**Architecture:** Node CLI `baton` (stdlib only) owns a `.baton/` dir of markdown briefs + `index.json`. Per-agent readers turn transcripts into a common turn list; an extractor builds a mechanical skeleton; a cheap model (invoked through the agent's own CLI) writes/refreshes prose. Thin integrations: rules snippet (any agent), Claude Code plugin (skills + hooks), Codex prompt.

**Tech Stack:** Node ≥ 20, ESM, `node:test`, `node:child_process`, `node:fs`. Zero dependencies.

**Spec:** `docs/superpowers/specs/2026-11-18-baton-design.md` (Round 2 section supersedes earlier sections where they conflict; product renamed `handover` → `baton`, dir `.baton/` → `.baton/`).

## Global Constraints

- Zero runtime dependencies; Node built-ins only.
- No API keys: models are invoked only via `claude -p --model <m>` or `codex exec -m <m>`; model + runner configurable in `.baton/config.json` (`{"runner":"claude","model":"haiku"}` default).
- Brief ≲ 150 lines; Lineage one line per ancestor.
- Mission copied verbatim from root; only root may change it.
- State section is written by code from git, never by a model.
- Transcripts are untrusted: never executed; secrets redacted before any write or model call. (load-bearing)
- `.baton/` added to `.gitignore` by `baton init` by default.
- Package name `@sriinnu/baton`, bin `baton`, repo `sriinnu/baton`.

## Review Focus

1. Session id not found in any store → clear error listing searched dirs, exit 1 (Task 4).
2. Not a git repo / detached HEAD → State says `not a git repo` / `detached at <sha>`, no crash (Task 2).
3. Runner binary (`claude`/`codex`) missing or model call fails during hook-driven `sync` → brief left unchanged, error logged to `.baton/sync.log`, hook exits 0 so the agent isn't blocked (Task 7).
4. Transcript contains `sk-…`/`ghp_…`/`AKIA…`/`Bearer …` tokens → redacted to `[REDACTED]` in skeleton and in text sent to model (Task 5).
5. Two `sync` runs on the same brief concurrently (Stop + SubagentStop fire together) → lockfile `.baton/<id>.lock`; second run skips (Task 7).

### Task 6: CLI core commands

**Files:** Create `bin/baton.js`, `src/commands.js`; Test `test/cli.test.js` (spawn `node bin/baton.js` in temp repo, `HOME` pointed at fixtures dir)

**Interfaces — Consumes:** Tasks 1–5. **Produces:** commands
- `init`
- `write [--name n] [--parent ref] [--agent a]` → scaffold with State, prints path
- `from <ref|--path p> [--name n] [--parent ref]` → locate+read+skeleton+scaffold; parent defaults to the existing brief for that session if any (continuation); prints path
- `show <ref>` → brief + live drift lines + warning if fill markers remain
- `child <parentRef> --task "…" [--agent a] [--agent-id x]` → child brief: Mission + Lineage (one line per ancestor from each brief's `Task` first line) + Task + parent's Decisions/Dead ends + `## Report back` text: `Before this session ends, run \`baton write --parent <id>\` (or update this brief) with Done, Decisions, Dead ends.`
- `fold <childRef>` → appends one Lineage-style line + child's Decisions to parent brief
- `ls` → tree by parent
- exit 1 + message on unknown ref.

- [ ] Step 1: tests: `init`; `from <fixtureId>` creates brief with State and markers; second `from` same id → new brief whose parent is the first (continuation) and same mission; `child` contains Mission verbatim + Report back; `fold` adds line to parent; `show` prints drift after a new commit; unknown ref exit 1.
- [ ] Steps 2–5.

### Task 7: Cheap-model sync

**Files:** Create `src/model.js`, `src/sync.js`; Test `test/sync.test.js`

**Interfaces — Produces:**
- `runModel(prompt, cfg) -> Promise<string>`: `claude -p --model <m>` or `codex exec -m <m>`, prompt on stdin; test override `TAKEOVER_RUNNER=<path-to-fake-script>`.
- `sync(cwd, ref, {quiet}) -> {updated: boolean, reason?}`: lock `.baton/<id>.lock` (skip if held, `{updated:false, reason:'locked'}`); read transcript from `sourceOffset`; nothing new → no-op; else prompt = current brief + redacted new skeleton + instruction "update prose sections, keep Mission and State untouched, stay ≤150 lines, return the full brief"; then re-render State from git (code overwrites whatever model returned), verify Mission unchanged (else reject), write, advance `sourceOffset`.
- CLI: `sync <ref>`, `sync --hook` (reads hook JSON from stdin: `session_id`, `transcript_path`; registers brief if new). Hook mode always exits 0; errors → `.baton/sync.log`.

- [ ] Step 1: tests with fake runner: updates prose, advances offset; second sync with no new lines → no-op; model altering Mission → rejected, brief unchanged; runner exits 1 → brief unchanged, log written, `--hook` exit 0; held lock → skipped.
- [ ] Steps 2–5.

### Task 8: Arrival sanity check

**Files:** Create `src/check.js`; Test `test/check.test.js`

**Interfaces — Produces:**
- `check(cwd, ref, {run=true}) -> {ok: boolean, lines: string[]}`: drift vs State; runs brief's verification command (State line `verify: <cmd>`, argv split on spaces, timeout 120s) if present; fill markers present → not ok. Writes `## Check` section: `<iso date> <agent> ok|DRIFT: …`.
- CLI `check <ref>` exits 0 if ok, 2 if drift (agent must report to user before working).

- [ ] Step 1: tests: clean → ok; new commit → exit 2 with drift line; failing verify cmd → not ok; Check section written.
- [ ] Steps 2–5.

### Task 9: Integrations

**Files:** Create `rules/AGENTS.snippet.md`, `plugin/.claude-plugin/plugin.json`, `plugin/skills/pass/SKILL.md`, `plugin/skills/resume/SKILL.md`, `plugin/hooks/hooks.json`, `codex/baton.md`, `README.md`; Test `test/integrations.test.js`

- Snippet (≤ 40 lines): on leaving → `baton write`/fill markers; on arriving → `baton show <ref>` then `baton check <ref>`, report drift to user before any edit ("wash your feet"); when delegating → `baton child … --task` and pass only that brief; subagents obey `## Report back`; without the CLI, read/write `.baton/briefs/*.md` by hand in the same format.
- Hooks: `Stop`, `PreCompact`, `SubagentStop` → `baton sync --hook`.
- `/baton:pass [name]` skill: `baton from <current session id> --name`, fill markers, show path. `/baton:resume <id|name>` skill: show → check → continue or report drift.
- Codex prompt mirrors both; Codex `notify` config line documented in README.

- [ ] Step 1: tests: `plugin.json` and `hooks.json` parse and every hook command is `baton sync --hook`; every `baton <cmd>` mentioned in snippet/skills/README exists in `commands.js` dispatch table.
- [ ] Steps 2–5. Final: `node --test` all green; commit `feat: integrations`.
